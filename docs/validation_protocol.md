# Validation Protocol

## 1. Purpose

The objective of this document is to define the scientific validation protocol used by the **psynthea-validation** framework.

Rather than describing the software implementation, this document specifies the validation methodology that will be applied to synthetic cohorts generated by psynthea and, subsequently, compared with the original Java implementation of Synthea.

The protocol establishes:

* which properties of a synthetic cohort will be evaluated;
* how each property will be measured;
* which statistical methods will be applied;
* the implementation priority of each validation block.

The protocol acts as the scientific specification for the entire framework. Every metric implemented in the source code must correspond to one element described in this document.

---

# 2. Validation Objectives

The framework aims to answer the following research questions:

1. Is the generated cohort structurally correct?
2. Is the generated population demographically realistic?
3. Does the simulated epidemiology reproduce expected disease distributions?
4. Are clinical relationships internally consistent?
5. Is healthcare utilisation coherent?
6. Does psynthea behave similarly to the original Synthea engine?
7. Can the framework identify adaptations required for the Spanish National Health System?

---

# 3. Validation Philosophy

The validation process is organised into independent validation domains.

Each domain evaluates one aspect of the generated cohort.

The domains are intentionally independent to ensure modularity and to allow future extensions without modifying existing validation modules.

The framework distinguishes between:

* descriptive analysis;
* statistical comparison;
* clinical validation;
* structural validation.

This separation follows the Single Responsibility Principle adopted throughout the project.

---

# 4. Validation Domains

The complete validation protocol is divided into eight domains.

## Domain 1 — Structural Integrity

Purpose

Verify that the generated cohort is structurally valid.

Questions

* Are all identifiers unique?
* Are foreign-key relationships consistent?
* Are there missing mandatory tables?
* Are there duplicate records?

Priority

★★★★★

---

## Domain 2 — Demographic Validation

Purpose

Evaluate whether the demographic characteristics of the cohort are realistic.

Variables

* number of patients;
* age;
* sex;
* age distribution;
* population pyramid.

Priority

★★★★★

---

## Domain 3 — Healthcare Utilisation

Purpose

Evaluate how patients interact with the healthcare system.

Variables

* encounters per patient;
* encounter types;
* encounters by age;
* encounters by sex.

Priority

★★★★★

---

## Domain 4 — Clinical Conditions

Purpose

Evaluate disease-related metrics.

Variables

* prevalence;
* age at onset;
* disease duration;
* recurrence;
* multimorbidity.

Priority

★★★★★

---

## Domain 5 — Medication

Purpose

Evaluate pharmacological treatment.

Variables

* medications per patient;
* treatment duration;
* medication frequency;
* medication-condition relationships.

Priority

★★★★☆

---

## Domain 6 — Observations

Purpose

Evaluate generated observations.

Variables

* observation counts;
* observation types;
* missing values;
* observation distributions;
* Ground Truth consistency.

Priority

★★★★★

---

## Domain 7 — Clinical Consistency

Purpose

Verify expected clinical relationships.

Examples

* breast cancer should predominantly occur in women;
* prostate cancer should occur exclusively in men;
* otitis media should primarily affect children;
* hypertension prevalence should increase with age;
* diabetes should be associated with obesity.

Priority

★★★★★

---

## Domain 8 — Comparative Validation

Purpose

Compare psynthea with the original Java implementation.

Variables

* demographic distributions;
* disease prevalence;
* encounter distributions;
* medication distributions;
* observation distributions.

Priority

★★★★★

# 6. Statistical Methods

Whenever cohort comparisons are required, the framework will employ standard statistical methods.

Continuous variables

* mean;
* median;
* standard deviation;
* confidence intervals;
* Student's t-test;
* Mann–Whitney U test;
* Kolmogorov–Smirnov test.

Categorical variables

* proportions;
* Chi-square test;
* Fisher's exact test (when appropriate).

Effect size

* Cohen's d;
* absolute difference;
* relative difference.

A significance level of α = 0.05 will be used by default.

# 7. Validation Workflow

Every validation experiment follows the same sequence.

```text
Synthetic Cohort

↓

Loaders

↓

ValidationCohort

↓

Descriptive Metrics

↓

Statistical Analysis

↓

Visualisation

↓

Validation Report
```

The same workflow will later be applied to both psynthea and the original Java implementation.
